Prompt-as-Code Architecture

Treating AI instructions with the same rigor as application code.

Decoupled Logic

We separated the Agent Orchestration (Python) from the Cognitive Instructions (YAML).

Why this matters:
  • Versioning: Git track `prompts_v1.yaml` vs `prompts_v2.yaml`.
  • A/B Testing: Run experiments to see if "Polite Persona" yields better SQL than "Strict Persona".
  • Safety: Hot-swap instructions to patch hallucinations without redeploying binaries.

Minimizing Hallucinations

How we reduced "Context Poisoning" via Just-In-Time (JIT) architecture.

Dynamic Prompt Injection

The System Prompt is not static. We inject the user's exact query into the prompt at runtime.

"Current Mission: Investigate {kafka_lag}"

Result: Precision

The LLM effectively "forgets" previous searches (e.g., Payment API) and focuses 100% on the current task (Kafka).

Schema-Aware SQL Generation

❌ Naive Approach
SELECT * FROM metrics
WHERE service_name = 'Auth'
Error: Column 'service_name' does not exist.
✅ Aether Approach
SELECT m.* FROM metrics m
JOIN services s ON m.service_id = s.id
WHERE lower(s.name) LIKE '%auth%' LIMIT 50
Result: 50 rows returned. (Correctly Joined)
⚠️ Limitations & Future Roadmap

SQL generation struggles with complex multi-hop joins (3+ tables). Solution: GraphRAG. We plan to replace SQL Joins with a Graph Database (ArangoDB) to model service dependencies as edges, making retrieval deterministic.

Automated Evaluation

"LLM-as-a-Judge"

We don't guess if the agent is improving. We grade it.

The Problem with Chatbots

An agent might get the right answer but use the wrong tools (e.g., guessing instead of looking up data). Manual log review is unscalable.

The Solution: `evaluate.py`

A script runs the agent against 50+ test cases. A stronger model (GPT-4o) reads the execution logs and grades them P/F based on a rubric.
